# ADR-001：V0 数据层选用 IndexedDB（Dexie），不用 sqlite-wasm

- 日期：2026-10-06
- 状态：已采纳
- 决策人：Xing（拍板） + yiyi（建议）

## 背景

练伴 V0 是 Web-first 产品（手机浏览器使用，Web 先行已定），单机先行，无后端。
需要持久化的数据：用户画像、训练历史、体重/围度、每日营养打卡、B站收藏、
用户绑定的音频，以及**用户导入的视频文件本身**（原型痛点：关掉页面视频就没了）。

曾考虑"沿用英语 agent 的 sqlite"：但 language-agent 的 sqlite 是跑在 Node 后端的
better-sqlite3；Web 端的 sqlite 只能是 sqlite-wasm（WASM 编译版 + OPFS 持久化），
和后端 sqlite 不是一回事。

## 决定

V0 数据层使用 **IndexedDB，通过 Dexie.js 封装**。

## 被否掉的选项

- **sqlite-wasm**：约 1MB+ 的 WASM 体积；异步 API 心智负担重；Blob（视频/音频）
  需要额外处理；本质是"为了 sqlite 而 sqlite"，性价比不如 Dexie。
- **后端 sqlite（better-sqlite3）**：V0 单机场景不需要服务端，为"以后可能要的
  同步"提前付出服务器成本与运维复杂度，违反宪法第 5 条（简单可演进）。

## 后果

- V0 零后端、可离线；视频/音频 Blob 直接存 IndexedDB，导入一次永久有效。
- V2 如做多端同步/双人模式，再引入后端 sqlite，前端做同步层（roadmap 已预留）。
- Dexie schema 见 `docs/prd/prd-v0.md` §4。
