# 练伴 Roadmap（总规划）

> 更新日期：2026-10-06
> 状态：V0 开发中

---

## 产品一句话

**陪伴式健康生活**：跟练有人带（运动），跟做有人教（饮食），数据诚实记录，情绪价值拉满。
从产后恢复场景起步，产后只是 5 大场景之一。

---

## V0：跟练闭环（当前）

**目标**：第一用户能连续用 14 天，完整跑通"选场景 → 跟练 → 记录 → 反馈"闭环。

**范围**（详见 `docs/prd/prd-v0.md`）：
- F1 跟练播放器（动画演示 + 语音数拍 + 节奏同步）
- F2 动作库（15 动作原子：多维属性/搜索/筛选/详情/进退阶/安全标签）
- F3 自建跟练、F4 当天自适应（一键降载）
- F5 场景体系（产后恢复/新手入门/减脂燃脂/塑形增肌/办公拉伸）
- F6 视频跟练（本地导入 + 分段编辑器 + B站轻量收藏）
- F7 配乐（Web Audio 合成 4 氛围 + 用户音频绑定）
- F8 数据记录（训练历史/体重曲线/围度/营养打卡，IndexedDB 持久化）
- F9 训练反馈（RPE → 自适应建议）、F10 情绪价值文案体系、F11 健康安全

**技术**：Web-first（手机浏览器），TypeScript + Vite，不引入重型 UI 框架；
数据层 Dexie.js (IndexedDB)，零后端，离线可用。见 `docs/decisions/ADR-001.md`。

**非目标**：后端/账号/同步、小程序/原生 App、饮食模块、精确卡路里、社交、B站视频解析下载。

---

## V1：健康饮食（下一阶段）

**方向**：不做"饮食记录"，做 **"跟做"** ——跟着练伴做一道菜。
（立论见 2026-10-06 头脑风暴：陪伴感是产品魂；跟练状态机/动作库模型可复用到做饭域；运动-饮食-数据形成闭环。）

**建议范围**：
- 菜品库：20–30 道起步，每道菜 = 食材 + 步骤 + 营养（蛋白/钙/铁每份）+ 难度时长 + 场景标签（哺乳期高钙/减脂高蛋白/15分钟快手）；内容从用户夫妻学做饭过程沉淀。
- 跟做模式：步骤式跟做 + 计时 + 语音（跟练播放器的孪生兄弟）。
- 吃后联动："今晚做了这道" → 蛋白/钙自动记入数据页，替代手动按钮。

**不做**：精确卡路里、买菜电商、社交。

**验证问题**（V1 只回答这一个）：用户愿不愿意跟着练伴做饭？

**待定**：北极星指标（每周跟做 3 顿 vs 蛋白钙达标率）、是否做双人模式。

## V2：候选

- 双人/家庭模式（夫妻一起用：一个练一个做/轮流）。
- 多端同步：引入后端（sqlite），前端做同步层。
- 小程序壳（如果 Web 验证后用户强烈要求微信内体验）。

## 远期
